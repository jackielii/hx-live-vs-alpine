Open state lives in `aria-expanded` on the button, which doubles as the accessibility contract. `attr['aria-expanded']` reads back a boolean, so `:hidden` is a plain negation.

Two fixes were needed against the installed htmx 4.0.0 (`node_modules/htmx.org/dist/ext/hx-live.js`), which differs from the checked-in hx-live docs:

- `attr` is a property-access proxy in this build, not a callable (`attrHandler.get` returns `readAttr(...)` directly), so `.attr('aria-expanded')` throws `TypeError: attr is not a function`. The docs' call-style example (`q(...).attr('aria-expanded')`) is stale; the fix is bracket property access, `q('previous button').attr['aria-expanded']`, both to read and to assign (`... .attr['aria-expanded'] = false`).
- Each `hx-on` listener htmx registers runs as its own async job, and the browser performs a microtask checkpoint between listener invocations even within one event's bubble phase. That drains hx-live's pending `:hidden` recompute (queued off the `aria-expanded` mutation) before the `outside` listener on the contents div runs, so by the time that listener's body executes, `this.hidden` already reflects the *new* (open) state — checking `!this.hidden` as a "was I just opened by this same click" guard (mirroring Alpine's synchronous `offsetWidth`/`offsetHeight` check) does not work here, it always sees the post-toggle state. The fix instead checks the click's target: `!q('previous button').contains(event.target) && (...)`, so a click on the toggle button itself is never treated as an outside click, regardless of timing.
