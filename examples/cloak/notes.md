Alpine removes `x-cloak` when it initialises an element, so a `[x-cloak] { display: none }` rule hides markup until then. hx-live has no cloak directive, but any attribute can be cleared imperatively: `hx-on:load="attr['hx-cloak'] = null"` removes the marker once the `load` event fires (`null`/`undefined` is what actually removes a generic attribute in hx-live 4.0.0 — assigning `false` only stringifies to `hx-cloak="false"`, which still matches the `[hx-cloak]` CSS selector), and the same CSS trick hides the element until then.

A static `:hx-cloak="null"` binding on the same element as `:hidden="true"` does not work: hx-live evaluates an element's bound attributes by walking its live `attributes` list in DOM order, and removing `hx-cloak` mid-walk (because it sits before `:hidden` in source order) shifts the list and skips the `:hidden` binding entirely, leaving the element visible. Moving the removal into an `hx-on:load` handler defers it to a separate pass, so it no longer interferes with sibling bindings.
